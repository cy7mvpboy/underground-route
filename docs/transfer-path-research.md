# 환승 통로(역 내부 도보 경로) 표시 방법 조사

조사일: 2026-11-10. 조사 방식: 웹 문서 열람 + Overpass 소규모 질의. 데이터 파일 다운로드, 가입, 키 발급은 하지 않았다.
표기 규칙: 출처 URL이 있는 것만 사실로 적었다. 확인하지 못한 것은 "확인 못 함"이라고 썼다.

## 1. 결론 요약

- 환승 통로 **벡터 경로(좌표선)를 무료로 공개한 데이터는 찾지 못했다.** 국토지리정보원(NGII)/브이월드의 지하철역 실내 데이터 제공 여부는 검색으로 확인 못 함.
- 실제로 쓸 수 있는 것은 세 가지다.
  1. 서울교통공사 **역 이용 안내도 JPG**: 승강장·환승 통로·엘리베이터·에스컬레이터 위치가 그려진 역별 그림. 이용허락 제한 없음.
  2. 서울교통공사 **환승역 환승거리·소요시간 CSV**: 145개 환승역의 최단 환승거리(m)와 시간(초). 숫자만 있고 경로 좌표는 없다.
  3. **카카오맵·네이버지도 딥링크**: 앱에서 환승 안내를 보게 하는 연결. 오프라인 불가.
- 제안했던 (1) 안내도 이미지 + (4) 딥링크 조합이 현재 확인된 범위에서 가장 낫다. 여기에 (2) 환승거리 CSV를 더하는 것이 가장 효과 대비 비용이 낮다. 직선은 "개략 방향선(점선)"으로 낮춰 표시한다.

## 3. 항목별 조사 결과

### 3.1 실내공간정보 (벡터)

- 국토지리정보원이 2023년 실내공간정보 구축사업을 위해 서울교통공사 역사 면적, 운영 현황, 건축 정보 등을 요청했다는 공지가 있다([검색 결과 중 공공데이터포털 안내](https://www.data.go.kr/data/15003164/openapi.do?recommendDataYn=Y)). 즉 사업은 있었지만 **일반 공개 여부·형식·범위는 확인 못 함**.
- 국토정보플랫폼(map.ngii.go.kr)과 브이월드(vworld.kr)에서 지하철역 실내 데이터 레이어/다운로드를 찾는 검색에서 근거를 얻지 못했다. 브이월드 벡터 API는 무료·공공누리 1유형으로 표시돼 있지만 실내 레이어와는 무관해 보인다([data.go.kr 15140371](https://data.go.kr/data/15140371/openapi.do)).
- 서울시 S-Map 안내에는 실내 영역에 공공건축물과 지하철역사가 포함된다고 쓰여 있다([서울시 보도자료 검색 결과](https://news.seoul.go.kr/gov/archives/516121)). 3D로 보는 서비스이고, 열린데이터광장에서 내려받는 데이터셋은 찾지 못했다.
- 과거 서울시 실내공간정보시스템은 지하철 역사 103곳 등을 OPEN API·3DS·KML-Collada·CityGML로 공개한다고 보도됐다([업다운뉴스](https://www.updownnews.co.kr/news/articleView.html?idxno=47554)). 2010년대 자료이고 현재 접속 가능 여부는 확인 못 함(`indoormap.seoul.go.kr`은 이번 조회에서 이름 해석 실패).
- 교통안전공단, 국가철도공단, 코레일의 실내지도는 조사하지 못했다(확인 못 함).
- 정리: **무료 벡터 환승 경로를 확정적으로 쓸 수 있는 출처는 없다.** 가능성은 열려 있으나 4일 일정에서 기대하면 안 된다.

### 3.2 환승 경로 텍스트/단계

- 서울교통공사 환승역 거리·소요시간: 145개 환승역, 필드 `연번, 호선, 환승역명, 환승노선, 환승거리, 환승소요시간`, CSV, 이용허락 제한 없음, 최종 수정 2026-10-16, 환승소요시간은 환승거리를 1.2 m/s로 나눈 값, 엘리베이터 이용 등 실제 동선과 다를 수 있다고 명시([15044419](https://www.data.go.kr/data/15044419/fileData.do)). 열린데이터광장 쪽은 공공누리 1유형이며 2016년분부터 과거 버전이 있다([OA-13290](https://data.seoul.go.kr/dataList/OA-13290/F/1/datasetView.do)).
- 단계별 환승 안내(예: "3번 출구 방향 계단 내려가 ...")를 담은 데이터는 검색에서 **찾지 못했다**(확인 못 함). 엘리베이터 환승 동선 데이터셋도 찾지 못했다.
- 서울시 지하철역 엘리베이터 위치정보 API는 JSON/XML, 제한 없음, 2022-01-11 수정([15098158](https://www.data.go.kr/data/15098158/openapi.do)). 필드·키 필요 여부는 페이지에 없다(확인 못 함).

### 3.3 시설 좌표

- 서울교통공사 편의시설 현황([15044443](https://www.data.go.kr/biz/dcat/metadata/15044443.do))은 설치 여부이며 포맷이 png로 적혀 있고 좌표 필드는 확인 못 함.
- 엘리베이터·에스컬레이터 길이·높이 CSV([15133412](https://www.data.go.kr/data/15133412/fileData.do))는 호기, 승강기번호, 길이·높이만 있고 좌표는 없다.
- 부산교통공사 엘리베이터 정보([15119875](https://www.data.go.kr/biz/dcat/metadata/15119875.do))는 출입구 번호·상세 위치·운행 층 범위이며 좌표는 없다. 서울 외 지역용.
- 승강장→계단→통로→승강장을 잇는 좌표는 공개 데이터에서 찾지 못했다. 시설 좌표로 근사 경로를 만드는 안은 **좌표 데이터가 없어 현재 불가**(확인 못 함 포함).

### 3.4 OSM 실내 커버리지 (Overpass, 반경 200m, 서울 대표 환승역)

도구: `underground-route-hackathon/0.1` User-Agent, overpass-api.de와 overpass.kumi.systems 번갈아 재시도. 서버가 502/타임아웃을 반복해 절반이 실패했다.
수치는 반경 200m 안에서 해당 태그를 가진 way 개수다. **연결성(두 호선 승강장이 하나의 보행 그래프로 이어지는지)은 검증하지 못했다.** 존재 여부만 본다.

| 역 | 결과 | level 태그 |
|---|---|---|
| 서울역 | railway=platform 10, public_transport=platform 18, indoor=yes 2, footway(level) 9, steps(level) 1 | -4, 0;1, 1, 2 |
| 시청 | railway=platform 2, public_transport=platform 2, indoor=yes 5, footway(layer) 9, footway(level) 3, elevator 1 | -1 |
| 종로3가 | railway=platform 2, public_transport=platform 2, indoor=yes 2, footway(layer) 5, steps(level) 4 | 0;-1 |
| 동대문역사문화공원 | footway(layer) 4, steps(layer) 1. 승강장·indoor 없음 | 없음 |
| 사당 | indoor=yes 9, highway=corridor 6, railway=platform 1, public_transport=platform 2, steps(layer) 3 | -3 |
| 신도림 | railway=platform 4, public_transport=platform 4만. 통로 없음 | 없음 |
| 고속터미널, 교대, 왕십리, 김포공항 | Overpass 502·타임아웃으로 4회 재시도 후 실패. **확인 못 함** | - |

해석:
- 서울역, 시청, 종로3가, 사당에 통로 비슷한 요소(footway/steps/corridor/indoor)가 일부 매핑돼 있다. 신도림, 동대문역사문화공원은 승강장 또는 통로가 거의 없다.
- 일부 역에만 단편적으로 있고, 호선 간 완전한 경로인지는 별도 검증이 필요하다. 전 역에 일관되게 기대할 수 없다.
- OSM 데이터는 ODbL이다(일반 사실, 이번에 출처 조회는 하지 않음).

### 3.5 카카오·네이버·기타 API

- **카카오맵 웹 길찾기 링크** (공식 [apis.map.kakao.com/web/guide](https://apis.map.kakao.com/web/guide/)):
  - `/link/by/{이동수단}/이름,위도,경도/이름,위도,경도` 형식. 이동수단은 `car`, `traffic`(대중교통), `walk`, `bicycle`.
  - `/link/from/이름,위도,경도/to/이름,위도,경도`, `/link/to/이름,위도,경도`도 있다.
  - 지하철 노선 보기: `/link/by/subway/{지역명}/출발역명/도착역명`. 지역명은 seoul, busan, daegu, gwangju, daejeon.
  - 경유지는 최대 5개이고 대중교통(`traffic`)에서는 경유지 불가. PC/모바일웹으로 자동 연결.
- **카카오 앱 스킴**: `kakaomap://route?ep={lat},{lng}&by=publictransit`(비공식 글 [dev.to](https://dev.to/piyaklabs/routing-around-google-maps-in-korea-naver-kakao-deep-links-weird-coordinates-and-ios-clipboard-25mf)에서 확인, 공식 iOS 문서는 확인 못 함). 해당 글은 `by` 값으로 `foot`, `car`, `publictransit`를 든다.
- **카카오 길찾기 REST**: 카카오맵 API 문서에 `GET https://dapi.kakao.com/v2/routing/publictraffic`(대중교통), `/v2/routing/walk`(도보), `/v2/routing/bicycle`이 있다([developers.kakao.com](http://developers.kakao.com/docs/ko/kakaomap/common)). 응답 필드(도보 구간의 실내 통로 좌표 여부)는 **확인 못 함**. 테스트 앱은 소규모 일일 쿼터가 적용된다는 카카오 운영진 답변이 있다([devtalk](https://devtalk.kakao.com/t/api-rest-code-10/150841)). 약관상 결과 표시 제한은 확인 못 함.
- **네이버 앱 스킴** ([공식](https://guide.ncloud-docs.com/docs/maps-url-scheme)): 대중교통 `nmap://route/public?slat=..&slng=..&sname=..&dlat=..&dlng=..&dname=..&appname=<앱 식별자>`. `appname`은 모든 URL에서 필수(웹이면 페이지 URL). 도보 `/route/walk`가 지원 동작으로 나열돼 있으나 가져온 본문에는 파라미터 표가 없었다(확인 못 함). 문서가 낡았다는 표시가 있고, 웹 URL(`map.naver.com`) 변형은 문서에서 확인 못 함. 정적 웹에서는 `intent://`(안드로이드)나 스킴 호출이 필요하다.
- **네이버클라우드 Directions 5/15**: 문서상 경유지 5개/15개, 옵션이 자동차 경로로 보이며 도보·대중교통은 언급이 없다([소개](https://guide.ncloud-docs.com/docs/en/application-maps-overview)). 무료 쿼터는 기본 계정에만 적용. 요금은 확인 못 함.
- **ODsay** ([레퍼런스](https://lab.odsay.com/guide/releaseReference)): 경로 `subPath`에 `trafficType`(1 지하철, 2 버스, 3 도보), `distance`, `sectionTime`(분)이 있다. 환승이 도보 구간으로 나오는지는 명세만으로는 확인 못 함. **실내 경로 좌표는 문서화되지 않음.** 출구 좌표(`startExitX/Y`)만 있다. 요금·한도는 공식 근거를 찾지 못했고, 개인 블로그가 "하루 1000건, 6개월 무료"라고 적었으나 시점 미상이라 신뢰 불가([블로그](https://hellobrocolli.tistory.com/179)).
- **T map 대중교통** ([가이드](https://transit.tmapmobility.com/guide/procedure), [샘플](https://tmap-public-skopenapi.readme.io/reference/대중교통-샘플-예제)): SK OPEN API에서 상품 구매 후 appKey 발급. 가격·무료 한도·표시 제한은 페이지에 없음(확인 못 함). 샘플 응답의 WALK leg에는 `steps[].linestring`이 있으나 샘플에 지하철 구간이 없어 **환승 통로 좌표 여부는 확인 못 함**.
- 공통 문제: 모두 호출형 API라 정적 GitHub Pages(키 노출)·오프라인·전시(전쟁 상황) 요구와 충돌한다.

### 3.6 그 외

- 서울교통공사 역사 건축 현황(276개 역사, 층수·면적 등)은 구조 파악에 참고만 된다([검색 결과](https://www.data.go.kr/data/15003164/openapi.do?recommendDataYn=Y)).
- 지하철역 좌표정보(서울교통빅데이터플랫폼)는 역 위치이지 통로가 아니다([t-data](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=36)).
- 철도 BIM, 국토부 실내 내비게이션 시범사업 데이터는 검색에서 근거 없음(확인 못 함).
- OA-11984 "역이용안내도"는 설명에 비상시 대피 경로를 이미지 URL로 제공한다고 되어 있다. 2025-03 이후 데이터는 파일로 제공되고 공공누리 1유형([OA-11984](https://data.seoul.go.kr/dataList/OA-11984/S/1/datasetView.do)). 같은 계열의 데이터포털 파일 15004974가 더 설명이 상세하고 "제한 없음"이다.

## 4. 추천

### 권장 조합 (무료, 오프라인 우선, 4일 일정)

1. **환승 거리·시간 숫자 (필수, 반나절)**: 환승역 거리 CSV를 앱 데이터에 내장. 환승 화면에 "환승 약 NNN m, 약 N분(1.2 m/s 기준, 엘리베이터·혼잡 미반영)" 표시. 출처 표기.
2. **안내도 이미지 링크 (핵심, 1~1.5일)**: 환승역 중 앱이 지원하는 역만 JPG를 골라 리사이즈·압축해 번들하거나 서비스 워커로 사전 캐시. 환승 화면에서 "역 안내도 보기" 버튼. 이미지 위에 선을 겹쳐 그리는 건 하지 않는다(좌표 기준이 없다). 사용 전에 파일 크기와 실제 이미지에 통로가 읽히는지 샘플 몇 장으로 확인한다. 이 두 항목은 직접 확인하지 못했다(확인 못 함).
3. **지도의 직선은 점선 "개략 방향"으로 낮추고** "실제 통로와 다를 수 있음"을 명시. 사용자가 지적한 문제를 표현으로 정직하게 풀어 준다.
4. **딥링크 (선택, 2시간)**: 온라인일 때 "카카오맵에서 환승 보기"(`https://map.kakao.com/link/by/walk/...` 또는 `.../by/subway/seoul/출발역/도착역`)와 네이버 앱 스킴. 오프라인에서는 숨기거나 비활성화.
5. **OSM 실내 데이터는 이번엔 보류**: 시청, 서울역, 종로3가, 사당 일부만 가능성이 있고 연결성 검증과 정제가 필요하다. 후속 과제로 남기고, 이미 연결이 확인된 역이 생기면 해당 역만 벡터로 덮어쓰는 방식이 안전하다.

### 사용자가 해야 할 일
- 가입·키 발급은 필요 없다(위 조합은 모두 키 불필요).
- 공공데이터포털에서 아래 두 파일을 직접 받아 주거나, 다운로드 승인을 해 달라. (이 조사에서는 다운로드하지 않았다.)
  - 서울교통공사_역이용안내도 (15004974)
  - 서울교통공사_환승역거리 소요시간 정보 (15044419)
  - 파일 데이터는 로그인 필요 여부를 확인하지 못했다. 로그인이 필요하면 사용자 계정으로 받아야 한다.
- 안내도 이미지가 오프라인 용량(앱 크기)에 부담이 되는지 결정(환승역 수십 개로 제한 권장).
- 국토지리정보원(NGII)·서울시에 실내공간정보 제공 여부를 문의할 생각이 있다면 후속 과제로 문의(4일 안에는 기대하지 않음).

### 4일 안에 불가능하거나 비추천
- NGII/브이월드 실내 벡터: 근거 부재(확인 못 함).
- 카카오·ODsay·T map API: 키 노출, 한도, 약관, 오프라인 불가. 통로 좌표도 확인 못 함.
- OSM 실내 데이터를 전면 적용: 커버리지 불균등, 연결성 미검증.
