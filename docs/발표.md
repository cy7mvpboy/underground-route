# 지하로 — 발표 구성안

COM's 해커톤 2026 · 주제: 전쟁 · 혼자 참가

실시간 발표용이다(소개 페이지·영상 없음). 슬라이드 원본은 `slides/index.html`, 만든 파일은 `web/slides/index.html`(서비스 주소 `/slides/`), PDF는 `docs/발표.pdf`다. '화면'은 슬라이드에 적힌 글 그대로이고, '말할 것'은 발표자 메모(N 키)의 단서다. 단서를 보고 자기 말로 한다(코드는 발표자가 직접 설명해야 하는 규칙).

- 흐름: 문제를 느끼게 → 지금 모습(한강) → 해결 한 줄 → 시연(가운데, 전체의 절반) → 어려웠던 결정 두 가지 → 폰 안에서 끝나는 구조 → 되는 것·안 되는 것, 바라는 모습, 부탁.
- 시연은 앱의 시연 모드(`#demo`, 14장면 이야기 하나)를 브라우저 탭으로 띄워서 한다. 5번 슬라이드는 앱이 안 열릴 때의 대비이자 PDF로 보는 사람용 시연 요약이다.
- 평가 기준(각 20점): 주제 적합성, 창의성, 기술성, 완성도, 실용성. 동점이면 완성도, 그다음 주제 적합성.
- 근거 문서: `README.md`, `docs/계획서.md`, `docs/코드설명.md`, `docs/data-check.md`, `docs/roads-shelters-check.md`, `web/js/demo.js`, `scripts/check_demo.js`.
- 화면 문장 규칙: 제목은 숫자·장소·행동이 든 사실 한 가지. 구호, 대칭 문장, 비유, 강조어, 번호 카드를 쓰지 않는다. 작은 이름표는 6·7번의 '어려웠던 것 1·2' 두 개뿐이다.

| 슬라이드 | 5분 버전 | 3분 버전 |
|---|---|---|
| 1 제목 | 10초 | 5초 |
| 2 문제 | 25초 | 15초 |
| 3 한강 하저터널 | 25초 | 15초 |

| 6 어려웠던 것 1 | 25초 | 뺌 |
| 7 어려웠던 것 2 | 25초 | 25초 |
| 8 폰 안에서 끝난다 | 15초 | 뺌 |

## 6. 어려웠던 것 1: 어디가 지하인가

- 화면:
  - 작은 이름표 "어려웠던 것 1"
  - 제목 "tunnel 태그가 있는 선로만 지하로 본다"
  - 코드 `scripts/build_graph.py` 298–304행 (원문 그대로)

    ```python
    def classify(tags):
        t, b = tags.get("tunnel"), tags.get("bridge")
        if t and t != "no":
            return "tunnel"
        if b and b != "no":
            return "bridge"
        return "ground"  # layer<0, covered=yes도 지상으로 둔다
    ```

  - "layer<0은 지하로 치지 않는다"
  - "경부선 금정~수원 약 16km는 OSM에서 layer=-1이지만 실제로는 지상이다"
  - 작은 줄 "경인일보: 금정~군포~당정 4.84km 지상 운행 (docs/data-check.md 4.4절)"
- 말할 것:
  - classify 하나가 지하·교량·지상 판정 전부
  - tunnel 태그(no 아님) → 지하, bridge → 교량, 나머지 지상
  - layer=-1만 있는 선로는 지상: 경부선 금정~수원, 선로 4줄
  - 전국에서 layer<0이고 tunnel 없는 본선 90.1km 중 63.6km가 이 경부선
  - 한계: 동대구처럼 역 건물 밑 선로를 tunnel로 그린 곳은 지하로 계산됨
- 평가: 기술성 (규칙 대응: 발표자가 코드를 직접 설명)
- 근거: 코드설명 §2.2, data-check §4.4

## 7. 어려웠던 것 2: 지하만 가는 길

- 화면:
  - 작은 이름표 "어려웠던 것 2"
  - 제목 "비용 = 길이 × 가중치", 옆에 "지하 1", "지상·교량 1000"
  - 코드 `web/js/graph.js` 188행 (한 줄을 화면에 맞게 두 줄로 나눔, 내용은 그대로)
    - `for (let e = 0; e < nEdges; e++) weight[e] = under.has(E.s[e]) ? g.weights.under : g.weights.exposed;`
  - 코드 `web/js/router.js` 101–104행 (들여쓰기만 줄임), 103행 강조, `blocked.has(ei)`와 `len[ei] * weight[ei]` 밑줄
    - `if (ei >= noWalk || (blocked && blocked.has(ei))) continue;`
    - `const w = adjNode[k];`
    - `const nc = c + len[ei] * weight[ei];`
    - `if (nc < cost[w]) { cost[w] = nc; prevEdge[w] = ei; prevNode[w] = v; heap.push(nc, w); }`
  - "앞이 막힘은 그 간선을 blocked에 넣고 같은 탐색을 다시 부른다"
- 말할 것:
  - graph.js 188: 간선마다 가중치. 구조가 지하면 1, 아니면 1000 → 지상 1m = 지하 1km
  - router.js 103: 다음 노드 비용 = 지금 비용 + 길이 × 가중치
  - 104: 더 싸면 갱신하고 힙에 넣기 → 가장 싼 길부터 넓혀 감
  - 101: 막힌 간선은 건너뜀 = 시연 장면 9의 '앞이 막힘'
  - 질문 대비: 대안은 지상 가중치 15로 다시 탐색 (23행 ALT), 다익스트라 전체는 71–108행
- 평가: 기술성, 창의성 (규칙 대응)
- 발표자 메모: 줄 번호와 코드는 2026-11-11 저장소 기준이다. 코드가 바뀌면 다시 확인한다. 3분 버전은 103행과 101행만.

## 질문 대비 메모

- 시연의 지상 거리: 시연 모드는 OSRM(실제 도보 길)을 쓰지 않아 출구까지 거리를 직선으로 추정한다. 인터넷이 될 때 앱은 지상 도보 구간을 실제 길로 다시 잰다(2026-11-11 라이브 사이트 확인: 시청 앞은 직선 60m, 실제 길 267m).
- 환승 통로가 지하인지: OSM에 거의 없어서 양쪽 승강장이 모두 지하면 지하 통로로 가정한다(`docs/graph-format.md` 7절).
- 대안 경로: 지상을 2km 이하로 더 걸어 시간이 20% 또는 30분 이상 줄면 한 줄로 제안한다(`web/js/router.js` 23행 ALT). 예: 옥수 → 압구정 지하 우선 24.0km, 대안은 지상 1.2km로 22km 짧음.
- 검증: 지하·지상 표시 40곳(장대터널 7, 도시철도 구간 21, 한강 횡단 12)을 위키백과·언론 자료와 대조해 틀린 표시를 찾지 못했다. 나무위키 64건 대조도 불일치 0.
