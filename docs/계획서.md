# 지하로 — 계획서

COM's 해커톤 2026 · 주제: 전쟁 · 혼자 참가

## 1. 한 줄 소개

전쟁으로 지상 이동이 위험할 때, 전국 철도망의 실제 터널 연결 구조를 분석해 지상에 나가는 거리가 가장 짧은 경로를 GPS와 인터넷 없이도 한 걸음씩 안내하는 웹 앱.

## 2. 문제

전쟁이 나면 지상 이동 자체가 위험해진다. 정부와 지자체의 전시 국민행동요령은 두 가지를 말한다.

- 무작정 피난하지 말고 정부 안내를 따른다.
- 공습·포격 때는 현재 위치에서 가장 가까운 대피 장소, 곧 지하철역·지하주차장 같은 지하로 들어간다.

(출처: [대한민국 정책브리핑](https://www.korea.kr/briefing/policyBriefingView.do?newsId=148746307), [영등포구청](https://www.ydp.go.kr/www/contents.do?key=3373), 국민재난안전포털 행동요령)

지금의 지도 앱은 이 지침을 따라갈 수 없다.

- 지하 구조를 모른다. 어느 역이 지하이고, 어느 구간이 터널이며, 어디서 지상으로 올라오는지 경로 계산에 쓰지 않는다.
- 터널을 걷는 상황을 모른다. 열차가 멈춘 선로를 따라 걷는 경로, 터널 갈림길, 환승 계단 위치를 안내하지 않는다.
- 통신과 GPS가 끊기면 쓸 수 없다. 지하에서는 GPS가 잡히지 않고, 전시에는 통신망도 불안하다.

## 3. 해결

지하로는 철도 선로를 지하(터널)·교량·지상으로 나눈 전국 그래프 위에서, 지상 노출이 가장 적은 길을 찾아 안내한다.

1. **고른다.** 출발·도착을 장소 검색, 지도 누르기, 내 위치로 정한다. 급하면 '가장 가까운 지하로 대피' 버튼 하나로 가까운 지하역 출구까지 안내받는다.
2. **본다.** 지상 노출 거리, 걷는 시간, 환승 횟수, 지상으로 나가야 하는 지점이 한 화면에 나온다. 지상을 조금 허용하면 훨씬 빠른 길이 있을 때만 대안을 한 줄로 알려 준다.
3. **걷는다.** 노선·방면·역·환승·갈림길 단위의 큰 글씨 안내를 따라간다. 지도에는 지금 단계가 강조된다. 역에서 '도착'을 누르면 위치가 바로잡힌다.
4. **막히면 다시 찾는다.** '앞이 막힘'을 누르면 그 구간을 빼고 마지막 확인 지점에서 다시 탐색한다. '여기서 나가기'는 가까운 지상 출구 후보를 보여 준다.

## 4. 핵심 기능

| 기능 | 무엇을 해 주나 |
|---|---|
| 지상 노출 최소 경로 | 지하로만 가는 길이 있으면 그 길을, 없으면 지상 구간이 가장 짧은 길을 고르고 노출 구간을 표시한다 |
| 대안 카드 | 지상을 조금 걸으면 시간이 20% 이상 또는 30분 이상 줄 때만 "지상 700m 걸으면 14km 짧아요"처럼 한 줄로 제안한다 |
| 출구·터널 출입구·차량기지 연결 | 역 출구뿐 아니라 선로가 지상으로 나오는 터널 출입구, 차량기지에서도 출발·도착할 수 있다 |
| 가장 가까운 지하로 | 한 번 눌러 가장 가까운 지하역 출구 후보 3곳을 거리순으로 보여 주고 안내한다 |
| 단계 안내 | 노선·선 이름(예: 3호선 · 일산선), 방면, 지나는 역, 환승 카드(승강장 깊이, 계단 위치)를 단계별로 보여 준다 |
| 갈림길 안내 | 역 사이에서 선로가 갈라지는 곳을 체크포인트로 삼아 왼쪽·오른쪽·직진과 갈라지는 방면을 Y자 그림으로 알려 준다 |
| 앞이 막힘 재탐색 | 붕괴·침수·연기 등으로 막힌 구간을 빼고 마지막 확인 역까지 되돌아가는 거리를 포함해 다시 찾는다. 막은 구간은 기기에 저장한다 |
| 여기서 나가기 | 지금 위치에서 지하로 닿을 수 있는 지상 출구(출구, 터널 출입구, 수직구·비상 출구, 차량기지)를 거리순으로 보여 준다 |
| 지하로 갈 수 있는 곳 | 도착한 역에서 지하만 따라 30분·1시간·2시간·4시간 안에 닿는 역을 지도에 시간대별로 칠한다 |
| 저장 장소 | 집, 가족 약속 장소를 저장해 그곳까지 지하로 가는 경로를 바로 찾는다. 기기 안에만 저장한다 |
| 역 안 통로 모양 | 서울은 서울시 지하도 자료로 출구와 환승 통로를 실제 통로 모양으로 그린다 |
| 걸음 기반 위치 추정 | 폰 가속도 센서로 걸음을 세고 보폭을 자동으로 보정해, GPS가 없는 터널 안에서 위치를 추정한다 |
| 내 위치 | GPS가 잡히는 곳은 실제 위치를, 안 잡히는 곳은 추정 위치를 모양이 다른 표시로 보여 준다 |
| 오프라인 동작 | 한 번 열어 두면 앱과 철도망 데이터가 기기에 저장되어 인터넷 없이 경로 탐색·안내가 된다 |
| 장소 검색 | 시군구·읍면동, 병원·학교·관공서, 아파트 단지 등 6만여 곳을 오프라인으로 검색하고, 인터넷이 되면 온라인 검색을 더한다 |
| 시연 모드 | 발표 무대 화면(stage/)에서 이야기 하나를 장면 17개로 GPS·인터넷 없이 재생한다 (아래) |

시연 이야기(명동 → 수서): 평소 수서역을 가족 약속 장소로 저장 → 명동 거리에서 공습경보 → 가장 가까운 지하로(명동역 출구) → 4호선 승강장에서 수서까지 지하 경로 탐색 → 실제 3·4호선 연결선로 갈림길 통과 → 한강 하저터널(5호선 광나루–천호) 막힘 → 마지막으로 확인한 곳까지 875m 되돌아가 다시 찾음, 39.1km·지상 노출 0m(5호선 마포–여의나루) → 대안 카드 "지상 720m 걸으면 18km 짧아요"를 골라 왕십리의 수인분당선 지상 구간 722m를 지나 수인분당선 하저터널(서울숲–압구정로데오)로 한강을 건넘 → 수서 도착, 지하에 들어간 뒤 지상 노출 722m → 수서에서 동탄까지도 32.4km 전 구간 지하로 이어짐.

## 5. 데이터와 기술

### 데이터 출처

| 데이터 | 출처 | 쓰는 곳 |
|---|---|---|
| 철도 선로·역·출입구 | OpenStreetMap (ODbL) | 지하·교량·지상 구조, 역, 출구, 터널 출입구 |
| 환승 거리, 역 깊이, 역세권 | 서울교통공사 (서울 열린데이터광장·공공데이터포털) | 환승 거리·시간, 승강장 깊이, 출구 주변 지명 |
| 철도역 빠른 환승 정보 | 국토교통부 | 환승 계단 위치 |
| 지하철역 연계 지하도 공간정보 | 서울시 (공공데이터포털) | 서울 역 안 통로 모양 |
| 도보 길찾기 | FOSSGIS OSRM | 지상 도보 구간의 실제 길 (인터넷이 될 때) |
| 장소 검색 | Photon (온라인), OSM 기반 오프라인 색인 | 목적지 검색 |

### 처리 방식

1. **그래프 만들기 (미리 한 번, Python 표준 라이브러리).** OSM 선로를 역·분기점 단위 간선으로 나누고 각 간선을 `tunnel` 태그로 지하·교량·지상으로 분류한다. 환승역에는 환승 간선을 더한다. 결과는 파일 하나(`graph.json`)다.
2. **경로 탐색 (브라우저 다익스트라).** 비용은 길이 × 가중치이고 지상 1m를 지하 1km와 같게 계산한다. 지하로만 가는 길이 있으면 자동으로 그 길이 뽑히고, 없으면 지상 노출이 가장 짧은 길이 뽑힌다. 서버 없이 정적 파일로 동작한다.
3. **오프라인.** 서비스 워커로 앱과 데이터를 기기에 저장한다. 배포는 GitHub Pages(무료)다.

### 전국 그래프 규모

| 항목 | 값 |
|---|---|
| 대상 | 전국 운행 철도 (도시철도·광역전철·일반철도·고속철도) |
| 본선 선로 | 10,122km 중 터널 36.3% (복선은 두 번 셈) |
| 역 | 1,275곳 (지하역 577곳) |
| 출구 | 4,551곳 |
| 환승 | 425건 (서울교통공사 실측 거리 포함) |

### 검증

- **지하 판정 규칙.** `tunnel` 태그만 지하로 본다. `layer<0`만 있는 선로는 경부선 금정~수원처럼 실제로는 지상인 경우가 있어 지상으로 둔다.
- **출처 대조.** 장대터널 7곳, 도시철도 구간 21곳, 서울 한강 철도 횡단 12곳, 총 40곳을 위키백과·언론 자료와 대조했고 틀린 표시를 찾지 못했다. 나무위키 지상·지하 구간 64건 대조에서는 불일치가 0건이다 (일치 60, 애매 3, 못 찾음 1).
- **자동 검사.** Node 검사 13개를 돌린다. 브라우저의 JavaScript 경로 탐색이 Python 기준 구현과 같은 경로·거리·안내 문장을 내는지, 안내·재탐색·도달 범위·갈림길·걸음 추정 등이 기대대로 동작하는지 확인한다.

## 6. 차별점

- **지하 연결 구조 분석.** 지도 앱이 길만 찾는 곳에서, 어디가 지하로 이어지고 어디서 끊기는지를 계산한다. 예를 들어 서울에서 한강을 지하로만 건너는 길은 5호선 하저터널 두 곳뿐이다. 수인분당선·8호선·서해선 하저터널은 한쪽 강변에서 지상으로 나온다. 이 분석이 경로와 대안 판단에 그대로 쓰인다.
- **터널 안에서 쓰는 안내.** 갈림길의 왼쪽·오른쪽과 방면, 환승 승강장 깊이와 계단 위치, 지상 출구 후보 종류(출구·터널 출입구·수직구·차량기지)는 걷는 사람이 선로 위에서 실제로 필요로 하는 정보다.
- **GPS 없이 위치 잡기.** 걸음 수·보폭 기반 추정과 역·갈림길에서 누르는 '도착'·'통과' 확인을 합쳐, 지하에서도 남은 거리를 보여 준다.
- **끊김을 전제로 한 설계.** 앱을 연 뒤에는 데이터를 기기에 받아 두어 연결이 끊겨도 탐색·검색·안내·재탐색이 된다.
- **전국 범위.** 수도권뿐 아니라 부산·대구·대전·광주 등 도시철도가 있는 도시와 일반철도 구간까지 한 그래프로 다룬다.

## 7. 실용성

- **공식 지침과 같은 방향이다.** '가장 가까운 지하로' 버튼이 행동요령 그대로 동작한다. 앱은 지침을 대신하지 않고 지하로 가는 길을 구체화한다.
- **글을 줄인 화면이다.** 걷는 사람이 할 일(어디로, 어느 쪽, 얼마나, 몇 분)만 큰 글씨로 보여 준다. 어두운 화면이 기본이라 지하와 야간, 배터리에 맞다.
- **GPS·통신 없이 동작한다.** 경로 탐색, 단계 안내, 막힘 재탐색, 위치 추정이 모두 기기 안에서 돈다. 인터넷이 되면 도보 구간을 실제 길로 바꾸는 정도만 더한다.
- **설치와 비용이 없다.** 링크만 열면 되고, 서버·계정·유료 서비스가 필요 없다.
- **쓸 사람이 분명하다.** 평소 지하철 이용자라면 누구나 자기 역 주변에서 바로 써 볼 수 있다.

## 8. 가정과 안전 원칙

설계 가정

- 전시 상황에서 열차 운행이 멈추고 전기가 끊겨 선로를 걸어서 이동할 수 있다고 가정한다.
- 터널 안 보행 속도는 시속 3~4km로 잡고 화면에서 바꿀 수 있다.
- 실시간 피해 정보는 다루지 않는다. 막힌 곳은 사용자가 직접 표시하거나 미리 만든 상황을 고른다.
- 공개 데이터만 쓴다. 비공개 연결선이나 비상 통로 정보는 쓰지 않는다.
- 전시 상황을 전제로 시설의 평시 운영 시간과 출입 통제는 경로 계산에 넣지 않는다. 정전 때 멈추는 엘리베이터 경로 같은 항목도 넣지 않는다.

안전 원칙

- 평시에는 철도 터널에 들어가면 안 된다는 안내를 처음 열 때와 정보 탭에 항상 보여 준다.
- 지상 노출 구간은 색과 거리로 눈에 띄게 표시한다.
- 데이터 기준 시점을 README에 밝힌다. OSM은 2026-11-10 기준이고, 서울시 지하도 자료는 2021년 무렵 기준이다. 자료가 없는 곳은 점선 등 다른 표시로 구분한다.
- 철도 외 시설(지하상가, 도로 터널, 민방위 대피소)은 경로에 넣지 않았다. 자료 품질을 조사한 뒤 확장 방향으로만 정리했다.
